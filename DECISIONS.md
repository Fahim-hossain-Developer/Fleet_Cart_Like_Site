- 2026-11-02: Dependency installation uses official Git sources with TLS trust configured. For the distribution-only PHPStan package, bootstrap caches the exact locked official codeload archive using Composer's cache key; an existing lock checksum is checked when provided. - 2026-11-02: Current user authorizes Phase 1 and addon Section 12 mapping. The specific mapping overrides the addon's earlier blanket delay until Phases 0–2. Backfill Phase 0 security rules and an executable leak-test scaffold now; finish full security scanning in Phase 7.
- 2026-11-02: Phase 1 implements catalog-backed portions of B1–B5. Cart buttons/line badges, currency conversion, profile persistence, blog widgets, flash-sale and sales-based badges remain with their prerequisite phases; no fabricated sales or mislabeled currency amounts. Quick view exposes product/variant details now and gains cart submission in Phase 2.
- 2026-11-02: Clone images by physical copy rather than shared-file references; independent deletion and conversions remain safe. Catalog CSV is an explicit new-simple-product contract with row reports and no overwrite; XLSX is not introduced in Phase 1's CSV-specific scope.
- 2026-11-02: MySQL FULLTEXT integration tests use committed records and DatabaseMigrations; rollback-isolated feature tests cannot demonstrate InnoDB FULLTEXT visibility. SQLite uses LIKE fallback.
- 2026-11-02: Catalog filters and price sorting use the active sale/minimum-active-variant amount shown on the storefront, not regular list price. Base currency display remains fixed until actual currency rates are implemented in Phase 2.
- 2026-11-02: Current request authorizes Phase 2 after environment publication. Implement cart/checkout and mapped addon gifts, account-at-checkout, quick-view cart actions and manual currency conversion; stop before Phase 3.
- 2026-11-02: Inventory deducts transactionally on placement in Phase 2, including pending COD/manual orders. Configurable confirmation/payment-time reservation and cancellation/restocking belong with Phase 3 order transitions. No optional checkout-start hold is enabled yet.
- 2026-11-02: Matching an existing guest phone/email never attaches an order to that account or signs the shopper in. New optional accounts receive a time-limited setup link; verified customer login/account management remains Phase 3. Mail/SMS use local log delivery in this environment.
- 2026-11-02: All authoritative totals and payment amounts stay in the base currency. Manually maintained display rates are integer parts-per-million, snapshotted on orders; provider adapters remain Phase 6. Gift fees are explicit and refundable with an unfulfilled full cancellation; later fulfilled refunds require the Phase 3 policy.
- 2026-11-02: Gift fee precedence: per-product override, then highest category override, charged per unit; if any line overrides exist their sum replaces the order-wide default. Otherwise charge one order-wide fee. Gift tax is configured separately. Gift details are discarded when the gift toggle is off.
- 2026-11-02: Catalog price filters are explicitly labeled in the base currency; cards use the selected manual display currency. Checkout shows authoritative base-currency totals and records display-rate snapshots. Automatic FX providers remain Phase 6.
- 2026-11-02: Account setup and order confirmations use durable retry records. Setup bearer tokens are stored hashed for validation and encrypted only while delivery is pending, then the delivery payload is cleared. Notification failures never undo or fail a committed order response. Local SMS uses private development logs, not a claimed live SMS integration.
- 2026-11-02: Included tax is snapshotted separately from additional tax; checkout displays added tax plus a note for tax already in prices so its summary reconciles to the total.

- 2026-11-02: The current user explicitly authorizes Phase 3 — Orders & Customers; stop before Phase 4. Preserve the Phase 2 branch/history, create phase-3-orders-customers and push the completed phase under the existing authorization.
- 2026-11-02: Email ownership is established only through an atomic single-use email code. Password login/reset and matching contacts do not claim guest orders. First verification revokes passwords/sessions created before proof of ownership to prevent pre-account takeover; the verified session may set a new password for ten minutes. SMS and role-configured admin email OTP remain with Phase 4/6 prerequisites.
- 2026-11-02: Stock policy is snapshotted per order: placement default, confirmation or first payment. Deferred deduction is not a reservation. Shipping always ensures deduction. Per-item deducted/restocked counters bound cancellation and RMA release.
- 2026-11-02: Phase 3 refunds are explicit receipts for money manually returned, never an external transfer. Full unshipped cancellation can refund gift/delivery/tax; after shipment only approved returned merchandise is refundable. Gift wrapping, gift tax and delivery are retained. One accepted RMA per order may contain several lines/quantities; rejected requests can be resubmitted.
- 2026-11-02: Staff edits change quantities before payment/shipment while retaining immutable original item ratios, tax rates, absolute discount and delivery/gift charges. Legacy taxed lines without an exact rate snapshot are protected from recalculation. Manual COD creation uses the real checkout engine; required custom options use storefront checkout.
- 2026-11-02: Dompdf remains the PDF engine. Because it does not reliably shape Bangla, local Pango/HarfBuzz renders Bangla runs with bundled OFL static Noto Sans Bengali fonts into private trimmed images; English stays selectable. This adds a Pango/Fontconfig/process-execution hosting requirement, explicitly documented for native/shared hosts. No remote font fetching or TLS bypass.
- 2026-11-02: Customer erasure is an auditable request/support process subject to accounting retention, not automatic record deletion. CSV exports are synchronous and bounded to 5,000 records; larger queued reports remain Phase 6.
- 2026-11-02: A real MySQL manual-order race exposed a repeatable-read snapshot issue in firstOrCreate recovery. An upsert locks the stable idempotency cart, followed by current locking reads, before adding items or looking up the order. Independent workers now verify replay without duplicate stock/orders.
