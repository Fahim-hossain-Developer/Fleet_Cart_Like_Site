## Implemented architecture

- `ContentModel` has translated title/body/excerpt, publication status, enable flag, sort and windows. `ValidateContent` checks links/media/tree/typed config; `SafeContent` sanitizes output and generates vetted video embeds. Each concrete entity has a factory/policy and Filament editor. `ContentController` serves scheduled CMS data; private previews are signed plus staff authorization. `SectionCatalog` drives 21 homepage types. Preserve draft-category isolation in blog sections and later sitemap/feed queries.
- `ContentSeeder` runs once using the internal setting `content.starter_seeded`; never restore intentionally removed menu links or publish legal drafts on repeat setup. Contact messages have encrypted email/body and separate `messages.manage` permission (root/manager/support).
- `FlashPricing` supplies PHP and SQL prices, `QuoteCart` checks cumulative SKU quantities under stable product/flash locks, `PlaceOrder` records `FlashAllocation`, `FlashInventory` releases once on cancellation/verified failure. Flash-allocated quantities are immutable. Automatic rules apply by priority, then coupons, before shipping/tax; snapshot automatic/coupon discounts and applied rule evidence. Zero-total orders have paid status/zero funds and enable entitlements without a fake receipt. Do not weaken Phase 4 financial guards.
- Product lists serialize limits under `ShoppingList` owner lock (compare=4, wishlist=100), scope guest keys to session HMAC, merge into authenticated account and prune unpublished items before additions.
- `PublishNotice` stores deduplicated Laravel-compatible private notifications and delivery outboxes. `NoticePreferences` defaults marketing email/SMS off; opted-in transport requires verified contact. `DeliverNotice` rechecks consent and sends a testable `StoreNoticeMail`. Product watches detect actual stock/price transitions; order jobs and callbacks create stable source-key notices. Independent account guards remain intact.
- Reviews require verified contact and, by default, a real fulfilled purchase; sandbox purchases do not qualify. One review per customer/product with revision, moderated aggregate ratings, safely reencoded WebP photos (metadata stripped; 4MB/3000px limit), useful-vote uniqueness, answered Q&A, configurable policy and optional recent delivered-order review requests. `PublishFeedbackNotice` retries from persisted pending/attempt fields. Customer edits clear obsolete replies/pending notifications. Core review migration 006 and outbox 007 are applied; add new migrations for further schema changes.
- Newsletter records encrypt emails/confirmation payload/unsubscribe token; hashes support lookup. Double opt-in never verifies/logs into a customer account. Confirmations expire/single use; unsubscribe supports a CSRF web confirmation and an exact stateless capability-token one-click POST. Campaign audience freezes after preparation; consumers recheck current membership/generation, skip opt-outs, don't consume attempts while paused, and never blindly resend ambiguous transport results. `NewsletterMessage.status=sent` means transport acceptance, not inbox delivery. No live external messages were sent. Campaign/subscriber UIs require marketing permission and show masked contacts. Membership/campaign migrations through 008 applied locally.
- `/offers` shows only actual available flash products and explicitly public coupons (`is_public` defaults false). Customers can save known coupon codes for expiry reminders; complete coverage for this new slice is still needed.

## Known checks / pitfalls

Latest full SQLite: 181 passed/1103 assertions; 16 lock-specific tests skipped. Larastan/Pint green at checkpoint. No Phase 5 MySQL/build/browser evidence yet. The full rollback suite caught SQLite refusing to drop indexed `notice_pending`; migration 007 now drops its index before the columns. Keep that fix.

Filament closure injection uses `$state`, `$record`, `$get`, `$query`; arbitrary parameter names can fail at runtime. TagsInput has no `maxItems`; use array rules. PHPStan dislikes nullsafe access on the left of `??`; use ordinary access with coalescing. Loop-created/arrow-function migration fields may need model PHPdoc. Pint removes unused imports, so adding later tests requires restoring needed imports or using FQCN. JSON model defaults must be serialized strings (review images `'[]'`), not raw arrays. Eloquent upsert bypasses encrypted casts; manually encrypt only on that boundary.

Generator scripts are under `/tmp/phase5-*.py`; do not rerun them blindly, because source was subsequently edited and formatted. Tests/logs are `/tmp/phase5-*.log`. PHP runs through Docker `scripts/cloud`; existing app owns port 8000 and scheduler is running. Build and HTTP/browser/database suites must use stable manifests sequentially.
